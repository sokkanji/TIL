# 제어 컴포넌트(Controlled Component)와 비제어 컴포넌트(Uncontrolled Component) 비교

제어 컴포넌트와 비제어 컴포넌트는 **React에서 폼(Form) 요소의 상태를 관리하는 방식**의 차이로, CDD(컴포넌트 주도 개발)에 중요한 영향을 준다.

<br/>

## 제어 컴포넌트 (Controlled Component)

- **정의:** **React의 State**가 폼 데이터의 **'Single Source of Truth(단일 진실 공급원)'** 역할을 하며, 폼 요소의 값이 완전히 React에 의해 제어되는 컴포넌트
- **특징:**
  - 폼 요소의 현재 값은 $\rightarrow$ **`value`** 또는 **`checked`** **Prop**을 통해 **React State**에서 가져온다.
  - 폼 요소의 값이 변경될 때마다 $\rightarrow$ **`onChange`** **Prop**에 전달된 **핸들러 함수**가 실행되어 **State를 업데이트**한다.
  - **값을 Prop**으로 받는다.
  - 렌더링 시점마다 항상 React State의 고유한 값을 가진다. (`useState`와 `onChange`는 **필수**)
- **작동 방식: "Push"**
  - 사용자가 값을 입력하면 <br/>
    1. `onChange`가 발생하고 <br/>
    2. 핸들러가 State를 업데이트하며 <br/>
    3. State 변경으로 인해 **컴포넌트가 재렌더링**되면서 <br/>
    4. `value` prop에 새로운 State 값이 다시 전달되어 **화면에 표시**된다.

<br/>
<br/>

```
// JavaScript - input의 값은 항상 React state의 값

<input value={value} onChange={handleChange} />
```

## 비제어 컴포넌트 (Uncontrolled Component)

- **정의:** 폼 데이터가 **DOM 자체**에 의해 관리되는 컴포넌트

- **특징:**
  - 폼 요소의 현재 값은 $\rightarrow$ **React State를 사용하지 않고**, DOM 요소 자체에서 관리한다.
  - 값을 가져오려면 $\rightarrow$ 주로 **`ref`**를 사용하여 DOM에 직접 접근한다.
  - `onChange` 핸들러는 **선택적**이다.
  - `ref`는 렌더링과는 **직접적인 관련 없이** DOM 노드에 접근하는 수단이다.
- **작동 방식: "Pull"**
  - 대부분의 경우, 폼 제출과 같은 특정 시점에 **`ref`**를 사용하여 DOM에서 값을 "끌어와야" 한다.

---

### 제어 vs 비제어 컴포넌트의 중요성

- **제어 컴포넌트**는 모든 폼 데이터가 React State 내에 있어 데이터 흐름을 예측 가능하게 만들고, 유효성 검사, 조건부 비활성화, 입력값 형식 지정 등을 실시간으로 처리하기 용이합니다. 이는 **CDD(컴포넌트 주도 개발) 환경**에서 컴포넌트의 독립성과 재사용성을 높이는 핵심이다.
- **비제어 컴포넌트**는 코드가 간결해질 수 있으나, 값을 얻기 위해 DOM에 직접 접근해야 하므로 **React의 단방향 데이터 흐름 원칙**을 일부 벗어납니다. 파일 업로드와 같이 DOM에 직접 접근해야 하는 경우나 간단한 폼에서 사용되기도 한다.

<br />
<br />

|             | Controlled (제어)                                                                             | Uncontrolled (비제어)                                                                            |
| ----------- | --------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------ |
| 지향점      | Push                                                                                          | Pull                                                                                             |
| 사용성      | Single Source of Truth(단일 진실 공급원)                                                      | 값을 담아내는 방법과<br>값을 가져오는 트리거 포인트 필요<br>이 모든 것을 관리하는 코드 직접 작성 |
| 성능        | 잦은 리렌더링                                                                                 | 구현하는 방법에 따라 다르지만 <br>성능에 이점이 있을 수 있음                                     |
| 동적 핸들링 | 상태를 중심으로 개발하기 때문에<br>상태 변경에 따른 핸들잉이 용이함                           | DOM을 직접 조작하기 때문에 핸들링이<br>어려워서 비용 증가                                        |
| 유효성 검사 | 상태 변경하면 UI 자동 반영하기 때문에 <br>개발자가 이를 위한 업데이트 코드 작성할 필요가 없음 | DOM을 직접 조작하기 때문에 핸들링이<br>어렵고 비용 증가                                          |
